本章将介绍多声部并行的写法，包括系统地使用 `@voices` 组织合奏，理解小节线同步与空行分段，以及用 `@stack` 或 `&` 在旋律中临时叠加另一段音符。

## 多声部
在单声部 `@voice` 的基础上，使用 `@voices` 包裹多个 `@voice`，即可让多个声部并行：
```jpfun
@voices(@voice(...), @voice(...), ...)
```

`@voices` 的每个参数都**必须是 `@voice`**。它们从同一时刻开始，各自按自己的节奏推进，并按参数顺序从上到下排列；`@voices` 还会在左侧加上括线，把它们组织成一组。

export const voicesFunctionExample = `\
@voices(
    @voice({1 2 3 5 | 3 2 1 -}, 主唱, "微风轻轻，吹过来。"),
    @voice({1, - 5, - | 1, - - -}, 伴奏, 啊啊啊)
)`;

<ScoreExample title="多声部例子" source={voicesFunctionExample} />

### 简写：连续的 `N:`
日常写谱不必每次都套上 `@voices`。把几个 `N:` 连续写在一起，jpFun 就会自动把它们合成一组；各自的歌词紧跟在各自的音符后面：

export const voicesSugarExample = `\
N(主唱): 1 2 3 5 | 3 2 1 -
L: 微风轻轻，吹过来。
N(伴奏): 1, - 5, - | 1, - - -
L: 啊啊啊`;

<ScoreExample title="连续写 N，组成多声部" source={voicesSugarExample} />

这里要注意：**相邻的 `N:` 表示同时演奏，不是前后两句。** 如果要接着写下一段，在两组之间留一个空行（正如 [谱面与页面排版](/docs/docs/tutorial/page) 所说，空行是谱面换行的语法糖）；如果需要两个多声部写在一行，可以用“内容块”的写法打断：

export const voicesSectionsExample = `\
N(主唱): 1 2 3 5 |
L: 微风轻轻，
N(伴奏): 1, - 5, - |\n
{   % 下面两个 voices 会在同一行
    N(主唱): 3 2 1 - |
    L: 吹过来。
    N(伴奏): 1, - - - |
}{
    N(主唱): 3 2 1 - |
    L: 吹过来。
    N(伴奏): 1, - - - |
    N: 5, - - - |
}`;

<ScoreExample title="多行和一行的写法" source={voicesSectionsExample} />


### 小节线是时间同步的锚点
**多声部中，小节线不只是视觉分隔，也是时间同步的锚点。** 各声部按先后顺序对应的小节线会对齐到同一时刻：如果某个声部先到达小节线，就等其他声部到达，再一起开始后面的内容。

export const voicesAnchorExample = `\
N(上声部): 1 2 | 3 4 5 6 ||
N(下声部): 1, - - - | 5, - ||`;

<ScoreExample title="在小节线处同步后再继续" source={voicesAnchorExample} />

上声部的 `1 2` 只占两拍，下声部的 `1, - - -` 占四拍，因此第一根小节线对齐到第四拍结束处。上声部的 `3` 不会紧接着 `2` 开始，而是等到这里，与下声部的 `5,` 同时进入下一小节。前面的 `1`、`2` 本身并没有被拉长，谱面也不会自动补出休止符。

这个例子特意让小节长短不同，以便看清同步效果。正常写谱仍应把各声部对应小节的时值写完整，需要停顿就明确写休止符；同步不能代替配拍检查。各声部的小节线也应保持对应，不要把某个声部中间的小节线随意省略，否则后面的小节线可能与其他声部的前一根错误配对。如果某个声部需要晚一点进入，应在它开头写休止符，而不是靠缩进或空格推迟。

### 音轨分配
在 jpFun 底层，每个 `@voices` 会从其所处的音轨分支出多个子音轨（像树枝一样），每个子音轨对应一个 `@voice`。不过这不意味着不同的 `@voices` 会分别分支：jpFun 会自动复用已经分支的音轨，所以轨道数相同的 `@voices` 之间，音轨会顺延下去。不过如果谱面第一行是二声部、第二行是三声部，此时就会变为一共5个子音轨，不会合并。

这个情况一般不会出现。这么设计是因为，jpFun 中一个轨道对应谱面的一行，这一行上的内容要对齐。正如上面的例子，一行里先出现了2声部，然后3声部，对齐方式是居中对齐。如果复用前面两个轨道，意味着前两行要对齐。这两个设计没有对错之分，只是 jpFun 选择了居中对齐、想表达“重开系统声部”的意图。


## 临时多声部
有时只想在旋律的某一小段叠加另一个声部，前后仍是一条连续的旋律。如果用 `@voices`，会看到新的多声部行内居中，并不会保持当前行的连贯。此时可以使用 `@stack`：
```jpfun
@stack({content1}, {content2}, ...)
```

各段内容从同一时刻开始，整体时长同样取最长的一段。与 `@voices` 不同，`@stack` 的第一段留在原来的谱线上，后续各段依次叠在它的上方，不添加多声部括线。

export const stackFunctionExample = `\
1 2 @stack({3. 4/}, {5 -}, {1'}) | 5 - - -\n
1 2 @voices(    % 如果使用 @voices 会断开当前旋律
    @voice({3. 4/}),
    @voice({5 -}),
    @voice({1'})
) | 5 - - -`;

<ScoreExample title="stack 和 voice 的对比" source={stackFunctionExample} />

### 用 `&` 简写
`@stack` 的简写是 `&`。在需要同时演奏的内容之间加上它即可；如果一边包含多个音符，要先用花括号把那一段收在一起：

export const stackSugarExample = `\
1 2 {3. 4/} & {5 -} & {1'} | 5 - - -`;

<ScoreExample title="用 & 叠加旋律" source={stackSugarExample} />

### 音轨分配
**`@stack` 的第一个参数会继续使用当前音轨**，后续的参数才会新开音轨；而 `@voices` 则是每个 `@voice` 都会新开音轨，父音轨承载 `@voices` 函数，不会泄露到里面每个 `@voice`。因此我们可以说，`@stack` 是临时的、局部的，而 `@voices` 是全局的、系统级的。

同一轨道（声部）上多次出现stack，音轨全部会复用。根据上文说过的“一个轨道对应一个对齐基线”的原则，一行内的多次 `@stack` 会相互影响，无论声部数是否一致：

## 小结
多声部有两种写法：
- 使用 `@voices` 或相邻的 `N:`，适合全局多声部，添加括线，按小节线同步。
- 使用 `@stack` 或 `&`，适合临时多声部，第一段留在原谱线，后续分支叠在上方，不添加括线。

请注意两者的音轨分配策略，这将影响最终导出的MIDI文件。
